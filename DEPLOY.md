# Деплой на shared-хостинг — единая папка `public_html`

## Как это устроено

`pull.php` живёт в корне проекта и копирует всё в ту папку, где сам лежит
(`__DIR__`) — значит корень проекта **и есть** `public_html`. Отдельной
"публичной" и "приватной" папки на хостинге не будет: всё содержимое
репозитория (lib/, data/, public/, vendor/ и т.д.) заливается в один
`public_html`, а `.htaccess` в корне блокирует прямой доступ ко всему,
что не должно открываться по URL, и перенаправляет остальные запросы
в `public/` (там лежит `index.php`, `api/`, `assets/`).

Сайт открывается на `https://.../` → Apache отдаёт `public/index.php`.
Деплой запускается на `https://.../pull.php`.

## Что теперь заблокировано `.htaccess`

Прямой HTTP-доступ закрыт для: `lib/`, `data/`, `storage/`, `cron/`,
`templates/`, `specs/`, `vendor/`, `.specify/`, `reference/`,
`graphify-out/`, `.git`, `config.php`, `config.example.php`,
`composer.json`/`composer.lock`, `pull-config.php`, `.gitignore` и любых
`*.md`. Листинг директорий отключён (`Options -Indexes`).

Открыто (и должно быть открыто): `public/` целиком — туда входят
`index.php`, `api/*.php`, `assets/css`, `assets/js`, `assets/img`.

## Важное изменение: подпись руководителя

Раньше загруженный файл подписи (`upload_signature`) сохранялся в
`public/uploads/signatures/signature.png` — то есть по прямой ссылке
`.../uploads/signatures/signature.png` его мог скачать кто угодно, зная
путь. Это реальный риск (подделка подписи на документах).

Теперь он сохраняется в `storage/signatures/` — эта папка вне `public/`
и дополнительно заблокирована в `.htaccess`. PDF (`lib/pdf.php`) читает
файл подписи с диска напрямую, а не по URL, так что для генерации КП
ничего не меняется — правьте только это.

Пустые `public/uploads/` и `public/uploads/signatures/` можно удалить
вручную (сессия не смогла их удалить — не было прав на удаление файлов
в подключённой папке).

## vendor/ теперь коммитится в git

Так как на хостинге нет SSH и `composer install` запустить негде,
`vendor/` (mpdf, PHPMailer и их зависимости) больше не в `.gitignore` —
я собрал его и положил прямо в проект. Закоммитьте и запушьте его вместе
с остальным кодом: `git add vendor && git commit`. При каждом
`pull.php` он будет обновляться вместе с кодом — отдельный шаг сборки
не нужен.

Если позже перейдёте на хостинг с SSH — можно вернуть `vendor/` в
`.gitignore` и ставить зависимости через `composer install` на сервере.

## Настройка `pull.php` (первый запуск)

Откройте `https://ваш-домен/pull.php` — увидите форму первичной
настройки (файла `pull-config.php` ещё нет). Заполните:

- **GitHub repository** — `owner/name` вашего репозитория.
- **Branch** — `main`.
- **Subdirectory** — `.` (весь репозиторий целиком).
- **GitHub token** — обязателен, если репозиторий приватный
  (fine-grained PAT с правом `Contents: Read` на этот репозиторий).
- **Password** — обязательно задайте пароль. Без него задеплоить сайт
  сможет кто угодно, кто узнает URL `pull.php`.
- **Files to preserve (keep_files)** — впишите:

  ```
  config.php, data, storage
  ```

  Это критично: `config.php` (реальные ключи/пароли) и `data`
  (SQLite-база, вложения) не попадают в git — их там нет специально.
  Если их не добавить в этот список, а «Purge» включён (он включён по
  умолчанию), **каждый повторный деплой удалит базу данных и настройки
  сервера**, потому что pull.php сочтёт их «лишними файлами, которых
  нет в репозитории». `pull.php` и `pull-config.php` сохраняются
  автоматически, их указывать не нужно.

- **Purge** — можно оставить включённым: он держит `public_html` в
  точном соответствии репозиторию (удаляет то, что убрали из кода), но
  только пока `data` и `storage` в списке исключений выше.

После сохранения формы `pull-config.php` создаётся автоматически (с
правами `0600`) и тоже заблокирован от прямого доступа.

## Что сделать один раз вручную на хостинге (не через git)

1. Скопировать `config.example.php` → `config.php` в корне
   `public_html` и вписать реальные ключи (БД сама создастся SQLite-
   файлом при первом запуске). Загружайте `config.php` через
   FTP/файловый менеджер — в git он никогда не попадёт.
2. Запустить `create_manager.php` один раз, чтобы создать первого
   менеджера (логин/пароль).
3. Настроить в панели хостинга cron на `cron/check_mail.php`,
   `cron/check_followups.php`, `cron/check_notifications.php`,
   `cron/sync_moysklad.php`, `cron/sync_knowledge.php` (пути — см. `plan.md`, D-004).

## Проверка

- `https://ваш-домен/` — должен открыться SPA (`public/index.php`).
- `https://ваш-домен/data/` — должно быть `403 Forbidden`.
- `https://ваш-домен/config.php` — `403 Forbidden`.
- `https://ваш-домен/pull-config.php` — `403 Forbidden`.
- `https://ваш-домен/storage/signatures/signature.png` — `403 Forbidden`.


## Модуль 002 — заказы, счета, чат компании

### Cron

Добавьте пятую задачу: `php /путь/к/проекту/cron/sync_moysklad.php` раз в
5 минут. Это догоняющая синхронизация с МойСклад — она подстрахует, если
вебхук не дошёл.

### Вебхуки МойСклад

После деплоя зайдите в «Настройки» → «Интеграция с МойСклад» и нажмите
«Зарегистрировать вебхуки». Требования:

- `APP_URL` в `config.php` — публичный **https**-адрес; на него МойСклад
  шлёт события (`/api/moysklad_hook.php?secret=...`).
- У токена МойСклад должны быть права на `webhook`, `customerorder` и
  `invoiceout`. Если прав нет, система не ломается: карточка компании
  подтягивает данные при открытии и при возврате на вкладку, плюс cron.

Секрет вебхука генерируется автоматически при первой миграции и лежит в
таблице `settings` (`moysklad_webhook_secret`). Адрес вебхука виден на
странице настроек — не публикуйте его.

### Новые папки хранения

`storage/attachments/` (вложения писем) и `storage/invoices/` (печатные
формы счетов) создаются автоматически, закрыты `.htaccess` вместе со
всем `storage/` и **не коммитятся** в git. Файлы отдаются только через
API с проверкой авторизации.

### lib/pdfparser

Библиотека разбора PDF (`smalot/pdfparser`, LGPL-3.0) лежит в
`lib/pdfparser/` и подключается собственным PSR-0 автозагрузчиком из
`lib/attachments.php` — не через composer. На хостинге ничего доставлять
не нужно, папка коммитится вместе с кодом. Обновление: заменить
содержимое `lib/pdfparser/src/` новой версией.

### OCR

Распознавание сканов идёт через Yandex Vision и использует уже
имеющиеся `YANDEX_API_KEY` и `YANDEX_FOLDER_ID`. Выключается в
«Настройки» → «Обработка писем» (запросы платные).

При HTTP 429 (лимит запросов Vision) вызов повторяется с паузой, а если
лимит держится — вложение остаётся без распознавания, в журнал попадает
предупреждение. При «Скачать весь архив» OCR не запускается вовсе:
текстовый слой PDF извлекается, а тысячи старых сканов не распознаются.

### Миграция БД

Схема обновляется автоматически при первом запросе после выкладки
(`runMigrations()` в `lib/bootstrap.php`, текущая `schema_version = 7`).
Перед выкладкой сделайте копию `data/kp.db`.


## Модуль 004 — админ-панель, логи, почта

### config.php стал необязательным

`config.php` теперь задаёт значения **по умолчанию**. Всё, что администратор
меняет в разделе «Админ → Настройки», лежит в базе (таблица `settings`,
префикс `cfg.`) и **имеет приоритет** над файлом. Если файл удалить с
сервера, сервис продолжит работать на значениях из интерфейса — там же
видно, откуда взято каждое значение, и есть кнопка «Сбросить».

Секреты (ключи нейросетей, токен МойСклад, пароли почты), введённые в
панели, шифруются ключом `data/secret.key`. Ключ создаётся сам при первом
сохранении, лежит рядом с базой, закрыт `.htaccess` и добавлен в
`.gitignore` — **не коммитьте его и не теряйте**: без него сохранённые
секреты придётся ввести заново.

### Почта

Ящиков теперь может быть несколько — они заводятся в «Админ → Почта»
(IMAP + SMTP, папки, привязка к менеджеру). При обновлении ящик из
`config.php` переносится в панель автоматически, ничего вводить заново не
нужно. Кнопки «Проверить IMAP» и «Проверить SMTP» работают **по значениям
формы**, то есть ящик можно проверить до сохранения.

Крон `cron/check_mail.php` теперь обходит все активные ящики: забирает
INBOX и папку «Отправленные» в общий архив (раздел «Почта») и только потом
превращает новые входящие в запросы КП. Синхронизация идёт по UID и не
трогает флаг «прочитано», так что в Outlook/Roundcube ничего не меняется.
Для чтения почты нужен модуль PHP `imap` — если его нет, панель и журнал
скажут об этом прямо, а отправка через SMTP продолжит работать.

### Ящик Яндекса (и Mail.ru, Gmail)

В форме ящика есть «Почтовый сервис». Выберите «Яндекс.Почта» — серверы
(`imap.yandex.ru:993`, `smtp.yandex.ru:465`), шифрование и папка
«Отправленные» подставятся сами, логином станет адрес ящика.

Пароль от аккаунта Яндекс **не подойдёт**: в «Яндекс ID → Безопасность →
Пароли приложений» создайте пароль для «Почты» и вставьте его в поля
пароля (достаточно ввести один раз — второе поле заполнится тем же; если
поле пароля SMTP пустое, отправка идёт с паролем IMAP).
«Проверить SMTP» показывает ответ сервера целиком — по нему видно,
отклонён пароль или у ящика вообще нет доступа к SMTP.
В настройках Яндекс.Почты должен быть включён IMAP. Ящик на своём домене
(Яндекс 360) настраивается так же: логин — полный адрес.

Проверьте кнопкой «Проверить IMAP» — она работает по значениям формы, до
сохранения, и покажет список папок ящика.

### Скачать весь архив писем

Обычный крон забирает только новое. Чтобы поднять в сервис всю переписку
ящика, нажмите «Скачать весь архив» в строке ящика: письма идут шагами,
панель показывает процент, кнопкой «стоп» загрузку можно прервать —
следующий запуск продолжит с того же места, ничего не задвоится. Старые
письма попадают в архив, но запросы КП из них НЕ создаются.

Большой ящик удобнее выкачивать кроном, без открытого браузера:

```
php cron/check_mail.php 1 backfill 300     # ящик №1, проход на 5 минут
```

Размер шага — в «Админ → Настройки → Почта» (`MAIL_BACKFILL_BATCH`,
`MAIL_BACKFILL_SECONDS`); на слабом хостинге ставьте меньше.
Кнопка «Выгрузить .mbox» отдаёт архив ящика файлом для Thunderbird.

### Логи

Ошибки PHP, отказы нейросети, IMAP/SMTP, МойСклад и все отказы API видны в
«Админ → Логи», у администратора в шапке — счётчик ошибок за сутки.
Журнал чистится сам по `LOG_RETENTION_DAYS` при каждом запуске
`cron/check_mail.php`.

Время в журнале — по `TIMEZONE` из настроек (SQLite пишет UTC, поэтому
метку ставит PHP). Одинаковые сообщения подряд не плодят строки: запись
одна, рядом счётчик «×N» и время последнего повтора.

Служебные `deprecated`-предупреждения PHP по умолчанию не пишутся —
включаются галочкой «Писать deprecated-предупреждения PHP» в
«Настройки → Логи», когда они нужны разработчику.

## Вход не проходит (экран логина перезагружается)

Признак: в обычном окне браузера логин возвращает на форму, в инкогнито всё
работает. Причина — залипшая cookie `PHPSESSID` от прежних сборок: если она
была выставлена по HTTPS с флагом `Secure`, браузер не даёт перезаписать её по
обычному HTTP, и сессия каждый раз теряется.

Сессия теперь живёт в собственной cookie `ATLANTSID`, а старая `PHPSESSID`
удаляется при входе и выходе, так что обновление снимает проблему само.
Если вход всё же не проходит, очистите cookie сайта вручную — приложение
теперь пишет об этом явно, вместо молчаливого возврата на форму.

## Приложение на телефоне и push (модуль 007)

Панель ставится на экран «Домой» и присылает уведомления при закрытом браузере.
Требования к хостингу — только те, что уже есть: `openssl` (с `openssl_pkey_derive`),
`curl`. Никакого Composer-пакета и никакого демона.

**Обязательное условие — HTTPS.** Без защищённого контекста браузер не даёт ни
service worker, ни установку приложения, ни push. По HTTP всё это просто не появится,
и «Настройки → Уведомления на телефон» так и напишет.

Проверить: «Настройки» → «Уведомления на телефон» → «🔔 Включить уведомления» →
«📨 Проверить». Уведомление должно прийти на это же устройство. Если нет —
там же раскрывается «Диагностика» с точным состоянием всех API, её можно скопировать
целиком. Со стороны сервера состояние видно в «Админ → Обзор».

Ключи VAPID генерируются сами при первом включении и хранятся в настройках
(приватный — зашифрованным). Менять их вручную не нужно: смена ключей отвяжет
все существующие подписки.

Файл `sw.js` отдаётся с `no-cache` и `Service-Worker-Allowed: /` — это уже прописано
в `.htaccess`. Если хостинг игнорирует `mod_headers`, после обновления панели
попросите администраторов один раз обновить страницу с очисткой кеша.

## Разбор входящей почты (модуль 006)

Служебная почта (Яндекс, МойСклад, хостинг, рассылки) отсеивается до обращения
к нейросети — список отправителей редактируется в «Настройки → Разбор входящей
почты → Служебные отправители». Если нужное письмо перестало доходить до менеджера,
причина отсева видна в разделе «Почта» рядом с письмом.

Поиск по вики использует SQLite FTS5. Если сборка SQLite на хостинге собрана без
FTS5, сервис сам откатится на прежний перебор в PHP — он медленнее, но работает;
состояние показано в «Админ → База знаний». Индекс перестраивается при синхронизации
вики; вручную — кнопкой там же или `php cron/sync_knowledge.php --force --reindex`.

## Векторный подбор позиций (модуль 009)

Подбор «подходящих позиций» умеет искать по смыслу, а не только по совпадению слов.
Для этого нужны ключ и Folder ID Yandex Cloud — те же, что для YandexGPT
(«Настройки → Нейросети»). Без них ничего настраивать не нужно: подбор остаётся
словесным, как раньше, и ошибок это не вызывает.

Индекс строится **шагами**, а не одним запросом: пачка из 20 позиций уходит
параллельно, шаг ограничен по времени и продолжается с того места, где остановился,
повторяя только те позиции, у которых изменилось название или описание.

- Вручную: «Настройки → Каталог товаров → Векторный поиск → Векторизовать каталог».
  Кнопка гоняет шаги в цикле и показывает прогресс; её можно закрыть и нажать позже.
- Кроном: `php /путь/к/проекту/cron/index_vectors.php --budget=60` раз в час.
  Ключ `--once` делает один шаг — для совсем слабого хостинга.

После большого импорта каталога из Excel индекс достроится сам при следующем запуске:
позиции с новым текстом попадут в очередь, остальные пропустятся.

Если API эмбеддингов доступен только через зеркало (как OpenRouter в модуле 008),
адрес задаётся в «Настройки → Все параметры → Подбор позиций → Адрес API эмбеддингов»,
прокси берётся тот же — `LLM_PROXY`.

## Почтовая программа: цепочки, «Отправленные», доски (модуль 010)

Письма показываются перепиской: всё с одной темой (с «Re:», «Fwd:» и без них)
собирается в одну цепочку по всем ящикам сразу. Ответ, отправленный с Gmail, виден
в той же цепочке, что и письмо, пришедшее на Яндекс. Отвечать можно из любого ящика —
письмо всё равно останется в этой переписке.

После обновления вся почта в архиве группируется автоматически (миграция схемы v11).

### Доска компаний (модуль 011)

После обновления (миграция схемы v13) «Письма» — это одна доска, а карточка на ней — компания:
вся переписка, запросы и КП открываются внутри карточки. Новые письма попадают во «Входящие»
сами при каждом открытии доски; глубина автозагрузки — «Настройки → Почта → Глубина автозагрузки
доски» (по умолчанию 180 дней), выключается там же (`BOARD_AUTOLOAD`). Колонка приёма помечена
`kind='inbox'` — её можно переименовать, письма всё равно будут падать в неё.

### Письмо как рабочее место (модуль 012)

Миграция схемы **v14** пересобирает цепочки писем: теперь переписка — это тема **и
отправитель**, поэтому одинаковые темы от разных компаний расходятся по своим карточкам.
Карточки доски автоматически переезжают на новые ключи, ничего перетаскивать заново не надо.
Первое открытие доски после обновления заново решает, кого положить во «Входящие».

Внутри письма теперь и таблица «Подходящие позиции» с кнопкой «Сформировать КП», и поле
ответа — отдельная страница запроса осталась только как глубокая ссылка. Иконки приложения
пересобраны из фирменного логотипа; на телефоне ярлык лучше переустановить, чтобы система
перечитала манифест.

**Копия в «Отправленных».** Раньше копия исходящего письма клалась в папку, записанную
в настройках ящика, и молча пропадала, если такой папки на сервере нет. Теперь
настоящая папка ищется в списке сервера («Отправленные», «Sent», «[Gmail]/Отправленные»,
«INBOX.Sent»), найденное имя сохраняется в ящике, а неудача видна сразу: красное
сообщение при отправке, отметка на письме в переписке и ошибка в логе.
Проверить состояние: «Настройки → Почта → кнопка «Отправленные» у ящика» — там же
показан список папок сервера и судьба последних десяти отправленных писем.

**Доски.** Раздел «Доски» — канбан в духе Trello: доски со своими названиями, колонки
(по умолчанию Входящие / В работе / КП отправлено / Ждём оплату / Закрыто) и карточки,
которые перетаскиваются мышью. Карточка держит всю переписку целиком, поэтому новый
ответ клиента появляется на той карточке, которая уже лежит в нужной колонке.
Положить переписку на доску можно кнопкой «▦ В доску» в самой переписке.
