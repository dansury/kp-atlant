# Атлант: выгрузка каталога для КП (`atlant.kpsync`)

Модуль для 1С-Битрикс на **atlant-armour.ru**. Отдаёт сервису подготовки
коммерческих предложений (**kp.atlant-armour.ru**) две вещи:

* адрес карточки товара по артикулу — из него КП печатает ссылку и QR-код;
* выгрузку всего каталога страницами — чтобы проставить ссылки разом, а не
  одним запросом на позицию.

Модуль **только читает**. Он ничего не создаёт, не меняет и не удаляет в
каталоге, поэтому его установка и удаление ничего не стоят: снесли — в КП
просто перестали печататься ссылки.

---

## Установка

Готовый архив — **`bitrix-module/atlant.kpsync.zip`** в этом репозитории
(собирается сам при каждом изменении модуля; вручную —
`php tools/build_bitrix_zip.php`). Его же отдаёт КП: *Настройки → Каталог
товаров → Сайт (Битрикс) → «⬇ Модуль для сайта (.zip)»*.

1. Распаковать архив на сайте в **`/local/modules/`** — внутри уже лежит папка `atlant.kpsync`
   (если такой папки нет — создать; можно и в `/bitrix/modules/`, но
   `/local/` переживает обновления Битрикса).

   Должно получиться: `/local/modules/atlant.kpsync/install/index.php`

2. В админке: **Marketplace → Установленные решения** (или
   *Настройки → Настройки продукта → Модули*) — найти
   «Атлант: выгрузка каталога для КП» и нажать **Установить**.

3. После установки экран покажет готовый адрес с токеном, например:

   ```
   https://atlant-armour.ru/bitrix/tools/atlant.kpsync/kp.php?token=8f2c…
   ```

   **Этот адрес нужно скопировать** — он понадобится на шаге 5.

4. **Настройки → Настройки продукта → Настройки модулей → Атлант: выгрузка
   каталога для КП**:

   | Поле | Что ставить |
   |---|---|
   | Выгрузка включена | да |
   | Токен | оставить сгенерированный |
   | ID инфоблоков каталога | пусто — возьмутся все торговые каталоги. Если каталогов несколько и нужен один — его ID через запятую |
   | Свойство с артикулом | `CML2_ARTICLE`, если каталог грузится из 1С. Иначе — код своего свойства |
   | Искать по названию | да |
   | Только активные товары | да |
   | Адрес сайта для ссылок | `https://atlant-armour.ru` |
   | Товаров в одной странице выгрузки | 500 |

5. В КП (**kp.atlant-armour.ru → Настройки → Сайт (Битрикс)**):

   * **Связь с сайтом** — включить;
   * **Адрес сайта** — `https://atlant-armour.ru`;
   * **Входящий вебхук Битрикс** — вставить адрес из шага 3.

   Остальное можно не трогать: шаблон адреса и шаблон поиска остаются
   запасными вариантами на случай, если модуль товар не нашёл.

6. В КП: **Настройки → Коммерческое предложение** — «Ссылка на товар на
   сайте» и «QR-код рядом со ссылкой» включены по умолчанию.

## Проверка

Открыть в браузере адрес из шага 3 с `&action=ping` — модуль ответит тем, что
видит сам:

```json
{"ok":true,"result":{"module":"atlant.kpsync","iblock_module":true,
 "iblocks":[21],"elements":1843,"article_prop":"CML2_ARTICLE",
 "base":"https://atlant-armour.ru"}}
```

`elements: 0` означает, что инфоблок выбран не тот — вернуться к шагу 4.

Поиск одного товара — подставить реальный артикул:

```
…/kp.php?token=…&article=BZ-5
```

```json
{"ok":true,"result":[{"ID":1024,"NAME":"Бронежилет Страж-5","ARTICLE":"BZ-5",
 "DETAIL_PAGE_URL":"https://atlant-armour.ru/catalog/bronezhilet-strazh-5/",
 "url":"https://atlant-armour.ru/catalog/bronezhilet-strazh-5/"}],"url":"…","total":1}
```

Пустой `url` — не ошибка: это ответ «такого артикула на сайте нет». КП
запоминает и его, чтобы не спрашивать про этот товар каждый раз.

## Что отвечает адрес

| Запрос | Что делает |
|---|---|
| `?token=…&article=BZ-5` | ищет товар: сначала по артикулу, потом по коду, потом по названию |
| `?token=…&code=…&name=…` | то же; можно передать любое сочетание |
| `?token=…&action=export&offset=0&limit=500` | страница каталога: артикул, код, название, адрес. `next` — смещение следующей страницы, `null` — конец |
| `?token=…&action=ping` | что модуль видит: инфоблоки, число товаров, свойство артикула |

Ответ всегда JSON и всегда `HTTP 200` — ошибка приходит как
`{"ok":false,"error":"…"}`, потому что на той стороне ответ разбирает парсер,
а не человек.

### Товары и торговые предложения

У торгового предложения нет собственной страницы, поэтому модуль отдаёт адрес
**товара**, которому предложение принадлежит. Это то же правило, по которому
КП показывает фото родителя для варианта из МойСклад.

## Обновление

1. Распаковать новый архив в `/local/modules/` **поверх** старой папки.
   Если модуль когда-то клали в `/bitrix/modules/`, там старую папку удалить:
   копия в `/local/modules/` важнее, и две разные копии путают.
2. *Marketplace → Установленные решения* → «Удалить», затем «Установить».
   Токен и настройки сохраняются; переустановка нужна, чтобы новые файлы
   легли в `/bitrix/tools` и `/bitrix/admin`.
3. Проверить: в настройках модуля строка «Версия модуля и папка» показывает
   новую версию, а в КП «Проверить связь» пишет «последняя».

## Экспорт товаров в Excel

**Сервисы → Атлант: экспорт товаров в Excel** (с 1.2.0) или
*Настройки → Настройки модулей → Атлант: выгрузка каталога для КП →*
**«Экспорт товаров в Excel»**. Файл `.xlsx`, по строке на товар:

| Внешний код | Название товара | Модификации и характеристики | Описание | Ссылка на сайте |
|---|---|---|---|---|
| `XML_ID` | `NAME` | по строке на торговое предложение: «Название — Размер: L; Цвет: олива» | `DETAIL_TEXT` (или `PREVIEW_TEXT`) текстом, без HTML | `DETAIL_PAGE_URL`, абсолютная |

Берутся те же инфоблоки и тот же фильтр «только активные», что у выгрузки для
КП. Тот же файл отдаёт адрес `kp.php?token=…&action=export_xlsx` — после
обновления модуля до 1.1.0 для этого адреса модуль нужно переустановить
(файл в `/bitrix/tools` копируется при установке); кнопка в настройках работает
сразу.

Начиная с 1.1.0 выгрузка для КП (`action=export`) несёт и `DESCRIPTION` —
описание товара на сайте. Сервис КП берёт его, когда описания нет в МойСклад
(порядок — настройка «Откуда описание товара»).

## Безопасность

* Токен сравнивается в постоянном времени и передаётся либо как `?token=`,
  либо заголовком `X-KP-Token`.
* Пустой токен оставляет адрес открытым — это осознанный режим для закрытого
  контура, и настройки об этом прямо говорят.
* Адрес закрыт от индексации (`X-Robots-Tag: noindex`) и не кэшируется.
* Модуль ничего не пишет, поэтому даже открытый адрес не даёт способа
  изменить каталог — только прочитать то, что и так опубликовано на сайте.

---

## Удаление

*Marketplace → Установленные решения → Удалить.* Файл
`/bitrix/tools/atlant.kpsync/kp.php` убирается, настройки остаются — повторная
установка не потребует вводить токен и инфоблоки заново.
