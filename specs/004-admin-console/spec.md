# Модуль 004 — Админ-панель: логи, настройки, почта, менеджеры, промпты

Статус: Implemented

## Зачем

До этого модуля всё техническое жило в `config.php` на сервере: ключи нейросетей,
пароли почты, токен МойСклад. Поменять модель или добавить второй почтовый ящик мог
только тот, у кого есть FTP. Ошибки уходили в серверный `error_log`, который на
shared-хостинге никто не открывает, — сбой IMAP или нейросети выглядел как «просто
ничего не пришло». Почта при этом жила отдельно от сервиса: в базу попадали только
письма, породившие запрос КП, — переписку целиком приходилось смотреть в почтовом
клиенте.

Модуль делает сервис самодостаточным: администратор видит и меняет всё в интерфейсе,
проверяет подключения одной кнопкой, читает журнал ошибок, а почта дублируется
целиком — и входящая, и исходящая.

## Требования

### Слои конфигурации (FR-046)

- **FR-046.1** `config.php` — значения ПО УМОЛЧАНИЮ. Всё, что изменено в интерфейсе,
  хранится в таблице `settings` с префиксом `cfg.` и ИМЕЕТ ПРИОРИТЕТ над файлом.
- **FR-046.2** Если `config.php` удалить с сервера, сервис продолжает работать на
  значениях из интерфейса. Файл больше не обязателен для запуска.
- **FR-046.3** Панель показывает у каждого параметра его источник: «из интерфейса»,
  «из config.php», «по умолчанию» — и даёт сбросить переопределение.
- **FR-046.4** Секреты (ключи, пароли, токен) шифруются в базе ключом
  `data/secret.key` и НИКОГДА не отдаются в браузер: наружу уходит только признак
  «задан» и последние 4 символа (Конституция, V).

### Журнал ошибок в интерфейсе (FR-047)

- **FR-047.1** Ошибки, предупреждения и фатальные ошибки PHP, отказы нейросети,
  IMAP/SMTP, МойСклад и все отказы API пишутся в таблицу `app_log`.
- **FR-047.2** Раздел «Админ → Логи»: фильтр по уровню, источнику и тексту,
  постраничный просмотр, карточка записи с контекстом и трассировкой.
- **FR-047.3** В шапке у администратора — счётчик ошибок за сутки.
- **FR-047.4** Пароли и ключи в контексте записи маскируются.
- **FR-047.5** Старые записи удаляются по `LOG_RETENTION_DAYS` (крон `check_mail.php`).

### Настройки и проверка подключений (FR-048)

- **FR-048.1** Все технические параметры правятся в интерфейсе: адрес сервиса, нейросети
  (провайдеры, порядок, модели, ключи), МойСклад, почта, уведомления, логирование.
- **FR-048.2** «Проверить МойСклад» — реальный запрос прав доступа.
- **FR-048.3** «Проверить IMAP» / «Проверить SMTP» — по ЗНАЧЕНИЯМ ФОРМЫ, до сохранения
  ящика; SMTP умеет отправить тестовое письмо на указанный адрес.
- **FR-048.4** «Проверить нейросеть» — короткий реальный запрос к выбранной модели.
- **FR-048.5** Модели выбираются из каталога (как в NeuroPro) либо вводятся слагом руками.

### Почта как надстройка над почтовым клиентом (FR-049)

- **FR-049.1** В архив `mail_messages` попадают ВСЕ письма: входящие из INBOX и
  исходящие из папки «Отправленные», а также всё, что сервис отправил сам.
- **FR-049.2** Синхронизация идёт по UID и НЕ трогает флаг `\Seen` — почтовый клиент
  менеджера не замечает работу сервиса.
- **FR-049.3** Письмо, отправленное из сервиса, кладётся в IMAP-папку «Отправленные»
  (`MAIL_APPEND_SENT`), чтобы обе стороны переписки совпадали в любом клиенте.
- **FR-049.4** Раздел «Почта»: фильтры по ящику и направлению, поиск, чтение письма,
  вложения, ответ с сохранением темы и цепочки (`In-Reply-To`).
- **FR-049.5** Тело письма показывается ТОЛЬКО текстом: HTML-версия в браузер не
  отдаётся (ни удалённых картинок, ни скриптов из чужого письма).

### Несколько ящиков и менеджеров (FR-050)

- **FR-050.1** Ящиков может быть несколько; у каждого свои IMAP/SMTP, папки, признак
  «создавать запросы из писем» и необязательная привязка к менеджеру.
- **FR-050.2** Менеджер видит свои ящики и общие; администратор — все.
- **FR-050.3** Менеджеры заводятся и правятся в интерфейсе. Строка, изменённая в панели,
  помечается `ui_managed` — `config.php` её больше не перезаписывает (FR-046.1 для людей).
- **FR-050.4** Последнего администратора нельзя разжаловать, отключить или удалить.
- **FR-050.5** Менеджер, за которым числятся запросы, КП или ящики, отключается, а не
  удаляется — иначе данные осиротеют.

### Технические промпты (FR-051)

- **FR-051.1** Системные промпты (`parse_request`, `cover_letter`, `normalize_names`,
  `followup`) правятся в интерфейсе; встроенный текст остаётся в коде и работает, пока
  переопределения нет.
- **FR-051.2** Каждое сохранение кладёт предыдущий текст в `prompt_history`; есть кнопка
  «вернуть встроенный».
- **FR-051.3** Плейсхолдеры `{{tov}}`, `{{few_shot}}`, `{{email_rules}}` подставляются
  кодом; незаполненный плейсхолдер вырезается, а не уходит в модель как есть.

### Почтовый сервис ящика: Яндекс, Mail.ru, Gmail (FR-052)

- **FR-052.1** У ящика есть «почтовый сервис». Выбор сервиса подставляет серверы,
  порты, шифрование и папку «Отправленные»; сервис угадывается по домену адреса,
  но администратор может выбрать его руками.
- **FR-052.2** Яндекс, Mail.ru и Gmail НЕ пускают по обычному паролю от аккаунта —
  ящику нужен **пароль приложения**. Форма говорит это прямо и даёт ссылку на
  страницу, где он создаётся; один пароль подставляется и в IMAP, и в SMTP.
- **FR-052.3** Для этих сервисов логин — полный адрес ящика (включая домен
  Яндекс 360), поэтому он заполняется из адреса автоматически.
- **FR-052.4** Имена IMAP-папок передаются в модифицированном UTF-7 (RFC 2060):
  русская папка «Отправленные» у Яндекса и Mail.ru открывается, а список папок
  в «Проверить IMAP» показывается по-русски.
- **FR-052.5** «Проверить IMAP» / «Проверить SMTP» применяют пресет к значениям
  формы, так что ящик проверяется, когда заполнены только адрес и пароль.

### Скачивание всего архива писем (FR-053)

- **FR-053.1** По каждому ящику можно скачать ВСЮ переписку, а не только новое:
  «Админ → Почта → Скачать весь архив» проходит INBOX и «Отправленные» с самого
  первого письма.
- **FR-053.2** Загрузка идёт шагами (`MAIL_BACKFILL_BATCH` писем, не дольше
  `MAIL_BACKFILL_SECONDS` на шаг) и ХРАНИТ КУРСОР: закрытая вкладка, таймаут
  shared-хостинга или ошибка сети не начинают всё заново — следующий запуск
  продолжает с того же письма. Панель показывает процент и позволяет остановить.
- **FR-053.3** Старые письма попадают в архив, но НЕ создают запросы КП и
  уведомления: трёхлетнее письмо — история, а не новый запрос.
- **FR-053.4** Повторная загрузка не задваивает архив (дедупликация по UID и
  `Message-ID`), а после полного прохода обычная синхронизация продолжает с конца
  архива, не перечитывая его.
- **FR-053.5** Тот же проход доступен из крона:
  `php cron/check_mail.php <mailbox_id> backfill <секунд>` — большой ящик
  выкачивается ночами, без открытого браузера.
- **FR-053.6** Архив ящика выгружается файлом `.mbox` (кнопка «Выгрузить .mbox»),
  который открывают Thunderbird и импортеры почтовых клиентов.

## Ограничения

- **C-013** Чтение почты требует расширения PHP `imap`. Его отсутствие — не молчаливый
  сбой: панель и журнал говорят об этом прямо, отправка через SMTP продолжает работать.
- **C-014** Шифрование секретов требует `ext-openssl`. Без него значения хранятся как
  есть (как и в `config.php`) — терять пароль ящика хуже, чем хранить его в базе,
  закрытой `.htaccess`.
- **C-015** Архив писем хранит тело до `MAIL_BODY_MAX_KB` (по умолчанию 512 КБ) —
  SQLite на shared-хостинге не файловое хранилище.
- **C-016** Полное скачивание архива ограничено теми же лимитами: вложения
  крупнее 25 МБ пропускаются, тело режется по `MAIL_BODY_MAX_KB`. Ящик на
  десятки тысяч писем выкачивается за несколько проходов, а не за один запрос.
- **C-017** Выгрузка `.mbox` отдаёт текстовую версию писем и заголовки цепочки;
  вложения остаются в разделе «Почта» и в `storage/` — mbox не пересобирает MIME.

## Схема (v4, v5)

| Таблица | Назначение |
|---|---|
| `app_log` | журнал: уровень, источник, сообщение, контекст, менеджер, URL |
| `mailboxes` | почтовые ящики: IMAP/SMTP, папки, менеджер, watermark UID, последняя ошибка |
| `mail_messages` | архив писем: направление, папка, UID, адреса, тело, связи с компанией и запросом |
| `prompts`, `prompt_history` | переопределения промптов и история правок |
| `settings` (`cfg.*`) | переопределения конфигурации |
| `managers` + `is_active`, `ui_managed`, `phone` | менеджеры из интерфейса |
| `attachments` + `mail_message_id` | вложения архивных писем |
| `mailboxes` + `provider`, `backfill_*` (v5) | почтовый сервис ящика и курсоры полного скачивания архива |

## Файлы

| Файл | Роль |
|---|---|
| `lib/settings.php` | слои конфигурации: БД → `config.php` → встроенное значение |
| `lib/crypt.php` | шифрование секретов ключом `data/secret.key` |
| `lib/logger.php` | журнал + перехват ошибок PHP |
| `lib/prompts.php` | реестр промптов, переопределения, история |
| `lib/mail.php` | пресеты сервисов, ящики, архив, отправка (`MailProviders`, `Mailboxes`, `MailArchive`, `Mailer`) |
| `lib/mailsync.php` | синхронизация папок по UID, полное скачивание архива, разбор писем в запросы |
| `lib/email.php` | IMAP-чтение (включая имена папок в UTF-7) и отправка через SMTP |
| `lib/managers.php` | менеджеры: создание, правка, отключение |
| `public/api/admin.php` | админ-API: настройки, ящики, менеджеры, промпты, логи, проверки |
| `public/api/mail.php` | почта: список, письмо, отправка, ответ, вложения |
